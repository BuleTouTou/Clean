# 小区、期名与栋座联合复核需求

## 1. 问题与目标

当前小区复核以“原始小区 + 原始栋座”为独立匹配键，因此同一小区包含多个栋座时会生成大量重复审核项。与此同时，栋座字典虽然包含 `期名` 字段，现有匹配索引却没有使用它，无法处理“1–15 号楼属于一期、16–30 号楼属于二期”这类业务关系。

本次改动的目标是：将栋座作为期名判断依据，把同一原始小区的审核项合并展示，并提供有安全边界的批量确认能力，减少操作数量且避免把不同期名的栋座错误地一键覆盖。

## 2. 用户故事

1. 作为清洗人员，我希望在小区候选旁看到该批次涉及的栋座，以便判断正确期名。
2. 作为清洗人员，我希望同一原始小区只显示一个审核组，避免在长列表中重复寻找相同小区。
3. 作为清洗人员，我希望能把一个期名一键应用到该小区所有兼容栋座，以减少重复操作。
4. 作为清洗人员，我希望存在栋座冲突时系统保留逐组选择能力，避免批量操作造成错误。
5. 作为复核人员，我希望历史报告能记录每个栋座最终采用的期名和确认方式，便于追溯。

## 3. 业务规则

- 匹配索引必须使用栋座字典中的 `楼盘 + 期名 + 座栋 + 单元`，不能继续忽略 `期名`。
- 同一原始小区下的数据按标准化后的原始栋座形成子组；相同栋座的多行数据只需确认一次。
- 候选小区必须显示标准输出名、行政区、商圈、可覆盖的原始栋座数量以及未覆盖/冲突栋座。
- 当某个候选期名能够唯一覆盖审核组内全部栋座时，允许“应用到全部栋座”。
- 当同一栋座在字典中对应多个期名，或候选期名无法覆盖全部栋座时，不允许无提示地全部覆盖；系统应只应用到兼容栋座，并把冲突项保留为待确认。
- 没有栋座值的数据仍可按小区名称进行匹配，但不得声称使用了栋座依据。
- 已保存规则必须至少精确到“原始小区 + 原始栋座”；旧的小区级规则可继续读取，但不得覆盖新的栋座级明确规则。
- 普通用户与管理员的数据权限、报告归属和 OSS 用户目录规则保持不变。

## 4. 验收标准（EARS）

### R1：栋座辅助判断

- 当原始数据已映射小区和栋座字段时，系统应在小区复核组中展示去重后的栋座及各自影响行数。
- 当栋座字典中存在期名信息时，系统应使用该期名过滤或排序小区候选，并展示候选覆盖情况。
- 当栋座唯一对应某一期名时，系统应自动选择该期名，并记录匹配依据为“栋座唯一对应期名”。
- 当同一栋座对应多个期名时，系统应进入人工复核，不得自动任选一期。

### R2：合并审核

- 当多条数据具有相同的标准化原始小区时，系统应将它们展示为一个小区审核组。
- 当审核组包含多个栋座时，系统应在组内按栋座形成子项，相同栋座的所有行共享一次选择结果。
- 当用户展开一个小区审核组时，系统应能看到每个栋座的候选期名、影响行数和匹配状态。

### R3：安全批量操作

- 当某个候选期名覆盖审核组内全部栋座且不存在冲突时，系统应提供“一键全部匹配”操作。
- 当候选期名只覆盖部分栋座时，系统应明确显示覆盖数量，并只允许“应用到兼容栋座”。
- 当批量操作后仍有冲突栋座时，系统应保留这些子项为待确认，并阻止用户误以为全部完成。
- 当用户改变批量选择时，系统应允许继续逐栋座修正，不锁死子项。

### R4：导出与追溯

- 当导出清洗结果时，系统应按每条记录所属栋座采用对应的小区期名。
- 当人工确认或批量确认发生时，系统应在规则快照和审计记录中保存原始小区、原始栋座、标准小区期名、确认方式和影响行数。
- 当同一原始小区的不同栋座选择不同期名时，系统应正确导出多个标准小区名，不得回退为小区级单一选择。

### R5：兼容与回归

- 当数据中没有栋座字段或栋座为空时，系统应继续支持现有的小区名称匹配流程。
- 当读取旧规则时，系统应保持兼容；当保存新规则时，应优先保存栋座级规则。
- 当执行现有出售或出租清洗流程时，字段映射、栋座/单元复核、报告权限和下载功能应保持可用。

## 5. 非目标

- 不根据连续楼号范围主观推断期名；只有字典关系能够证明时才自动匹配。
- 不允许对存在冲突的整个小区执行无条件覆盖。
- 本次不修改楼盘或栋座 Excel 字典内容。

## 6. 建议的默认交互

- 页面沿用当前工具的清华红、浅灰和 Naive UI 组件体系，避免引入新的视觉语言。
- 每个原始小区显示为一个可展开审核组；组头展示总行数、栋座数和待确认数。
- 组内以栋座为行，显示“原始栋座 / 影响行数 / 推荐期名 / 状态”。
- 候选期名区域显示 `覆盖 12/15 个栋座`，并分别提供“应用到全部栋座”或“应用到兼容栋座”。
- 系统不使用危险的一刀切按钮；批量操作后仍需清楚标记未解决项。
