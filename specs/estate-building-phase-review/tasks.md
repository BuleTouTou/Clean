# Implementation Plan

- [x] 1. 建立期名感知的字典模型与缓存
  - 为标准小区候选生成稳定候选 ID，确保同名不同期不会碰撞。
  - 从栋座字典建立 `楼盘 + 期名 + 座栋 + 单元` 索引，以及 `楼盘 + 栋座 -> 期名集合` 反向索引。
  - 以字典文件修改时间和大小作为缓存签名，文件替换后自动重新解析。
  - 保留无期名栋座数据，但禁止把它作为唯一期名证据。
  - 增加唯一期名、同栋多期和空期名索引测试。
  - _Requirement: R1, R5_

- [x] 2. 实现名称与栋座联合匹配
  - 将现有候选生成流程改为先匹配基础楼盘，再使用栋座期名关系过滤或排序候选。
  - 实现“栋座唯一对应期名”和“名称与栋座联合唯一匹配”自动确认路径。
  - 同一栋座对应多个期名、名称与栋座无交集或旧规则冲突时进入人工复核。
  - 无栋座字段或栋座为空时保留现有名称匹配回退路径。
  - 增加按栋座拆分一期/二期、冲突不自动选择和无栋座回退测试。
  - _Requirement: R1, R4, R5_

- [x] 3. 生成同小区父组和栋座子组
  - 后端内部继续保存栋座级平铺审核项，保证导出逐行决策准确。
  - API 响应按标准化原始小区合并父组，并提供原始名称、总行数、栋座数和待确认数。
  - 子组按栋座级决策键去重，返回原始栋座、影响行号和合法候选 ID。
  - 为父组候选计算全部覆盖、部分覆盖、唯一覆盖和冲突数量。
  - 增加同小区多栋座只返回一个父组的接口测试。
  - _Requirement: R2, R3_

- [x] 4. 实现安全批量确认与后端校验
  - 扩展复核请求，接收 `manual`、`batch-all` 和 `batch-compatible` 确认方式。
  - “一键匹配全部”仅对覆盖全部且各栋座唯一兼容的候选开放。
  - “匹配兼容栋座”只写入合法子项，冲突和无候选项继续保持未解决。
  - 后端逐项验证候选 ID 是否属于对应栋座子组；篡改或不兼容选择返回 400。
  - 批量操作后允许用户逐栋座修改选择。
  - 增加全部覆盖、部分覆盖、篡改候选和人工覆盖批量结果测试。
  - _Requirement: R3, R4_

- [x] 5. 改造楼盘审核界面
  - 为复核响应和提交请求建立明确 TypeScript 类型，移除该页面现有的 `@ts-nocheck` 和非必要 `any`。
  - 使用小区父组展示原始小区、栋座摘要、影响行数和待确认数。
  - 展示候选标准小区、城区、商圈、覆盖比例、唯一覆盖数和冲突数。
  - 根据后端标志显示“一键匹配全部”“匹配兼容栋座”或禁用原因。
  - 展开区按栋座展示推荐结果、匹配依据、状态及人工选择控件。
  - 批量选择后保持冲突项醒目，并允许逐项修正。
  - 保持当前品牌颜色、中文字体和 Naive UI 组件体系，不进行全站视觉重构。
  - _Requirement: R1, R2, R3_

- [x] 6. 升级规则保存、导出和审计快照
  - 新规则按栋座级决策键保存候选 ID、标准输出名和确认方式。
  - 同时兼容读取旧字符串规则；旧小区级规则只在无栋座或与当前栋座兼容时应用。
  - 导出阶段逐行使用栋座级决定，验证同一小区不同栋座能输出不同期名。
  - 规则快照记录原始小区、原始栋座、标准小区、确认方式和影响行数。
  - 审计记录区分自动、单项人工、全部批量和兼容批量确认。
  - _Requirement: R4, R5_

- [x] 7. 完成回归测试与真实字典抽样验证
  - 运行全部后端测试，确保出售、出租、认证、报告隔离和下载流程没有回归。
  - 使用合成数据覆盖“1–15 号楼一期、16–30 号楼二期”的导出结果。
  - 对真实字典执行只读抽样，验证多期楼盘、同栋多期和空期名场景。
  - 运行前端 TypeScript 检查和生产构建，确保没有新增类型抑制或构建警告。
  - _Requirement: R1, R4, R5_

- [x] 8. 完成浏览器交互验收与文档更新
  - 在 OrbStack 本地环境重建业务镜像并确认 PostgreSQL、MinIO 和应用健康。
  - 在浏览器验证同小区折叠、栋座摘要、全部应用、兼容应用、冲突保留和逐项修正。
  - 验证字段映射到楼盘审核、栋座审核和导出的完整相邻流程。
  - 检查目标页面和浏览器控制台没有新增错误。
  - 更新 README，说明联合匹配规则、安全批量条件和旧规则兼容边界。
  - _Requirement: R1, R2, R3, R4, R5_
